# Проверка базы

После изменений запускайте `knowledge-graph validate`. JSON содержит `valid`, `database`, `errors` и `warnings`. При ошибках код завершения 1; отчёт остаётся в stdout. Остальные команды отклоняют повреждённую базу до чтения и обхода.

Проверяются версия, обязательные поля, типы, уникальность ID, точки входа и концы связей, повторы, безопасные относительные пути. Каждый английский и русский документ должен существовать, быть UTF-8 и содержать текст. Повреждённый перевод — ошибка даже при чтении английского.

Недостижимые узлы дают предупреждения. Достижимость проверяется от всех точек входа в обоих направлениях, поэтому предупреждение означает отдельный компонент. Циклы допустимы, обход отслеживает посещённые ID.

`DATABASE_NOT_FOUND` предлагает `install DIR` или `--db PATH`. `DATABASE_EXISTS` защищает существующую базу. `INVALID_DATABASE` содержит подробности: исправьте манифест или документы, проверьте и обновите просмотрщик. `UNKNOWN_NODE` означает отсутствующий ID.

Проверки разработки: `uv sync --locked`, `uv run python -m unittest discover -s tests -v`, `uv build`, `uv run python tests/check_distribution.py`. Тесты проверяют обход, формат, переводы, установку, поиск базы, CLI, HTTP и ресурсы пакета. В браузере проверяются язык, история и стабильные размеры.
